- **TASK-022 (#81, PR #162) is merged and closed** — `observation` partitioned by `PARTITION BY RANGE (created_at)`, yearly (2024-2028) + `DEFAULT`, per **ADR-0008** (accepted, lis-engineering). Partitioning forces `observation`'s primary key to become composite `(id, created_at)` — Postgres requires partition-key columns in any unique/PK constraint — which breaks every FK that referenced `observation(id)` alone (`previous_observation_id`, `amendment_of`, `superseded_by`, `result_history.observation_id`). Resolved by adding a companion `*_created_at` column at each site and referencing the composite key, preserving full DB-enforced referential integrity on TASK-021's correction chain rather than dropping to unconstrained columns (a real decision, routed to ADR-0008's addendum rather than made silently). A new `fn_observation_link_created_at` `BEFORE INSERT` trigger auto-populates the companion columns so application call sites are unaffected. Verified for real against a running Postgres 16 instance, connected as `lis_app`: partition routing correct including the `DEFAULT` partition; RLS isolates transparently across all partitions (wrong tenant 0 rows); `ix_obs_trend` exists as a local index on every partition; the 5-year single-patient/analyte trend query runs in ~0.16ms on seeded volume; the correction/supersede chain populates all companion columns correctly end-to-end; ADR-0007's negative test (a standalone `UPDATE ... SET superseded_by` is rejected) still holds under the updated append-only guard.
