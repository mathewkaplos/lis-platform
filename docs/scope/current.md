- **`pnpm deploy`'s file-inclusion defaults to git/npm-ignore-style rules when a package has no `"files"` field** — and `dist/` is gitignored at this repo's root. Any workspace package that starts using `pnpm deploy --prod` for the first time needs an explicit `"files"` field, or its build output silently never ships. Confirmed against pnpm's own docs (`pnpm.io/cli/deploy`), not guessed.
- **`nest build`'s output path is only `dist/main.js` if `tsconfig.build.json` has an explicit (or correctly-inferred) `rootDir` of `src/`.** Adding any `.ts` config file (e.g. `vitest.config.ts`) directly in the package root — outside `src/` — silently shifts TypeScript's inferred rootDir and changes the output layout. This is a latent risk for any future sibling config file (e.g. if `apps/web` or `packages/*` ever add one) — check `tsconfig.build.json`'s `rootDir`/`exclude` explicitly whenever a new top-level config file is added to a package that also has its own Dockerfile `CMD` path.
